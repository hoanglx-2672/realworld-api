Đọc hiểu dự án & học NestJS qua code thật

Đi từ bức tranh tổng, theo chân một request thật qua từng tầng, rồi tới từng khái niệm NestJS. Mỗi khái niệm chỉ ra file trong dự án và bài học tương ứng trong learning/lessons/.

Cách đọcMở trang này một bên, VS Code một bên. Link tới file mã nguồn mở bản đọc trong trình duyệt; muốn sửa thì mở cùng đường dẫn trong VS Code. Gặp ô Thử thì làm thật, đừng chỉ đọc.

0. Chuẩn bị (5 phút)

cd realworld-api
npm run db:up          # Postgres trong Docker
npm run start:dev      # app ở http://localhost:3000/api, tự reload khi sửa code

Mở requests/auth.http trong VS Code (extension REST Client), bấm Send Request ở request 1 và 2. Bạn vừa đăng ký và đăng nhập. Phần còn lại giải thích chuyện gì đã xảy ra bên trong.

1. Bức tranh tổng

Dự án làm gì: backend API clone Medium theo spec RealWorld. Không có giao diện: client (web, mobile, Postman) gọi API và nhận JSON.

Đã có: đăng ký, đăng nhập, xem/sửa user hiện tại (JWT). Chưa có: articles, comments, profiles/follow, favorites.

Ba ý tưởng xuyên suốt

01

Module hoá

Mỗi feature là một thư mục + một Module tự chứa controller, service, entity của nó.

02

Dependency Injection

Class không tự new thứ nó cần: khai báo trong constructor, Nest đưa vào.

03

Decorator

@Controller, @IsEmail, @Column… gắn "nhãn" để Nest, class-validator, TypeORM biết phải làm gì.

2. Theo chân một request: PUT /api/user

Request này đi qua nhiều tầng nhất trong code hiện có. Gửi request 4 trong auth.http, rồi bấm lần lượt từng bước:

PUT /api/user
Authorization: Token eyJhbGci...
{"user": {"bio": "I like to skateboard"}}
ThửGửi request 10–12 (không token / Bearer / token hỏng): request dừng ở bước nào, dòng nào ném lỗi? Gửi request 7: decorator nào sinh ra từng câu lỗi?

Đọc thêm về thứ tự middleware → guard → interceptor → pipe → controller → filter: 17-faq/08-request-lifecycle.

5. Thứ tự đọc gợi ý (2–3 giờ)

  1. src/tags/: feature nhỏ nhất, đủ module / controller / service / repository. 10 phút.
  2. main.ts → app.setup.ts → app.module.ts: app khởi động thế nào.
  3. src/users/: users.module → users.controller → dto/register-user.dto → users.service (register, login) → user.mapper.
  4. src/auth/ → user.controller → users.service (getCurrent, update).
  5. src/common/: các mảnh dùng chung.
  6. Entity + migration: user.entity, article.entity, file trong src/database/migrations/.
  7. test/auth.e2e-spec.ts song song với research.md.
  8. review.md và qa.md: các lỗi thật đã gặp và cách sửa. Mỗi lỗi là một bài học.

7. Thuật ngữ

Tiếng AnhNghĩa trong dự án
ModuleGói một feature: controller + provider + import
ControllerLớp nhận request HTTP theo route
Provider / ServiceLớp @Injectable() chứa nghiệp vụ, được DI đưa vào nơi cần
DINest tự tạo và truyền phụ thuộc qua constructor
DTOClass mô tả dữ liệu vào, kèm luật kiểm tra
PipeBiến đổi / kiểm tra tham số trước khi vào controller
GuardQuyết định request có được đi tiếp (đăng nhập, quyền)
EntityClass ↔ bảng DB
RepositoryĐối tượng truy vấn một bảng (find, save…)
MigrationFile thay đổi schema, chạy được và hoàn tác được
JWTChuỗi đã ký chứa { sub: userId }, client gửi lại mỗi request
MapperHàm biến entity thành JSON trả ra ngoài
e2e testTest gửi HTTP thật vào app thật
